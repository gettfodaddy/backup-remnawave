# Backup & Restore

Резервное копирование и выборочное восстановление Remnawave и Bedolaga Bot на Ubuntu-сервере.

```text
backup-remnawave.sh       Создает и проверяет комплект резервной копии
restore-from-backup.sh    Возвращает выбранную PostgreSQL базу из архива
```

> **Важно:** `restore-from-backup.sh` восстанавливает только одну выбранную базу данных. Он не возвращает конфиги, Redis, сертификаты, файлы кабинета или Docker volumes. Выбор Bedolaga Bot не затрагивает базу и контейнеры панели Remnawave.

## Что входит в резервную копию

- PostgreSQL Remnawave: `db_remnawave.sql.gz`.
- PostgreSQL Bedolaga Bot: `db_bedolaga-bot.sql.gz`.
- Redis RDB бота, если Redis доступен.
- Найденные конфиги и файлы указанных проектов: Remnawave, бот, кабинет, Uptime Kuma, monitoring, Nginx, Let's Encrypt, Fail2ban и `/opt/scripts`.
- Манифест со статусами элементов и SHA-256; внешний архив также получает файл контрольной суммы.

Архив создается в `/opt/backups/remnawave/` под именем `backup_ДАТА_ВРЕМЯ_UTC.tar.gz`. Скрипт проверяет дампы и tar/gzip-архивы, защищает файлы правами доступа и не публикует итоговый архив, если один из двух обязательных PostgreSQL-дампов завершился ошибкой. Отсутствующие необязательные пути отмечаются как пропуск.

## Установка

Скопируй оба скрипта на сервер в `/opt/scripts/`, предварительно просмотрев их содержимое:

```bash
install -o root -g root -m 700 backup-remnawave.sh /opt/scripts/backup-remnawave.sh
install -o root -g root -m 700 restore-from-backup.sh /opt/scripts/restore-from-backup.sh
```

Запускай их от root. Требуются Docker, Bash и стандартные утилиты Ubuntu; для Telegram-отчета нужен `curl`, для формирования HTML-сообщения — `python3`.

## Настройка Telegram-отчета

Секреты не хранятся в скрипте. Создай защищенный файл:

```bash
install -o root -g root -m 600 /dev/null /etc/backup-remnawave.env
micro /etc/backup-remnawave.env
```

Добавь в него:

```bash
TELEGRAM_BOT_TOKEN='ТОКЕН_БОТА'
TELEGRAM_CHAT_ID='ID_ЧАТА'
```

Скрипт отправит в Telegram центрированную карточку в моноширинной рамке: статус, сервер, длительность, размер, список компонентов и SHA-256. Затем отдельным сообщением приложит архив. Если Telegram не настроен или не отвечает, готовый локальный архив сохраняется.

Если старый токен уже попадал в текст или репозиторий, отзови его через BotFather и используй новый. Не добавляй env-файл, дампы или ключи сертификатов в Git.

## Создать бэкап вручную

```bash
/opt/scripts/backup-remnawave.sh
```

Проверь код завершения, отчет и наличие архива с контрольной суммой:

```bash
echo $?
ls -lh /opt/backups/remnawave/
cd /opt/backups/remnawave
sha256sum -c backup_ДАТА_ВРЕМЯ_UTC.tar.gz.sha256
tar -tzf backup_ДАТА_ВРЕМЯ_UTC.tar.gz >/dev/null && echo 'Архив читается'
```

Подставь настоящее имя созданного архива вместо `backup_ДАТА_ВРЕМЯ_UTC.tar.gz`. Если обязательный дамп завершился с ошибкой, финальный архив не публикуется; закрытый каталог `.failed-*` остается для диагностики.

## Восстановить базу из бэкапа

Сначала убедись, что выбран правильный архив и текущая база обслуживает нужный сервис. Для восстановления из стандартного каталога запусти:

```bash
/opt/scripts/restore-from-backup.sh
```

Либо укажи архив явно:

```bash
/opt/scripts/restore-from-backup.sh /opt/backups/remnawave/backup_ДАТА_ВРЕМЯ_UTC.tar.gz
```

Далее скрипт:

1. Предложит выбрать базу Remnawave или Bedolaga Bot.
2. Покажет источник, контейнеры и базу назначения.
3. Проверит архив, gzip и совместимость major-версий PostgreSQL.
4. Сохранит текущую базу в `/root/backups/restore-from-backup-ДАТА/`.
5. Остановит только выбранный контейнер приложения, заменит выбранную базу и запустит приложение обратно.
6. При ошибке импорта попытается вернуть pre-restore дамп.

Внимательно проверь план. Чтобы подтвердить замену базы, введи `RESTORE` точно так, как просит скрипт. Если отменить операцию, база останется без изменений.

После восстановления проверь health контейнера и журналы соответствующего приложения. Не удаляй pre-restore дамп, пока не убедишься, что сервис работает.

### Границы восстановления

- **Remnawave:** заменяется только выбранная база панели.
- **Bedolaga Bot:** заменяется только база бота; сама Remnawave панель не изменяется.
- Конфиги, Redis RDB, сертификаты, файлы приложений, кабинет и Docker volumes автоматически не возвращаются.

Не запускай восстановление всего `pg_dumpall` напрямую в работающий PostgreSQL: архив содержит несколько баз и глобальные объекты кластера. Скрипт извлекает только секцию выбранной базы.

## Автоматический запуск каждые 3 часа

Открой root crontab:

```bash
crontab -e
```

Сохрани существующую задачу Certbot и добавь строку бэкапа:

```cron
0 3 1 * * certbot renew --quiet && systemctl reload nginx
0 */3 * * * /opt/scripts/backup-remnawave.sh >> /var/log/backup-remnawave.log 2>&1
```

`0 */3 * * *` запускает бэкап в 00:00, 03:00, 06:00, 09:00, 12:00, 15:00, 18:00 и 21:00 по часовому поясу сервера. Время в именах архивов и Telegram-отчете указано в UTC.

Не добавляй `\` в конец cron-строк, не используй `crontab -r` и не заменяй весь crontab: достаточно добавить одну новую строку через `crontab -e`.

Проверь сохраненное расписание и журнал:

```bash
crontab -l
tail -n 100 /var/log/backup-remnawave.log
```

По умолчанию локально хранятся архивы за 14 дней. Для изменения срока поправь `RETENTION_DAYS` в начале `backup-remnawave.sh`. Запуск защищен `flock`, поэтому два экземпляра не будут выполнять бэкап одновременно.

## Безопасность и проверка восстановления

Архив содержит `.env`, данные приложений и приватные ключи Let's Encrypt. Храни его только в закрытом каталоге; для второй копии используй защищенное зашифрованное хранилище вне сервера. Telegram-доставка удобна для оперативности, но не заменяет offsite backup.

Планово проверь восстановление на отдельном тестовом окружении. Наличие архива и успешная проверка SHA-256 подтверждают целостность файла, но только пробное восстановление подтверждает пригодность данных и конфигурации.
